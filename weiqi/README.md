# 围棋 · 5×5 / 6×6

一个无需安装、打开即玩的网页围棋。支持 **5 × 5** 与 **6 × 6** 棋盘，玩家可以选择执黑或执白，由启发式蒙特卡洛树搜索（MCTS）AI 担任对手。

## 运行

直接双击 `index.html` 即可游玩。页面为纯静态 HTML/CSS/JavaScript，不依赖任何第三方库，也不需构建。

更推荐用本地 HTTP 服务打开，这样 AI 会在 Web Worker 中计算，思考时界面仍保持流畅：

```powershell
cd weiqi
python -m http.server 8000
```

然后访问 `http://localhost:8000/`。若直接以 `file://` 打开，浏览器会限制 Worker，页面会自动降级到主线程计算，功能不受影响；此时复盘分析期间界面可能会短暂停顿。

## 功能

- 5 × 5 / 6 × 6 两种棋盘，可随时开始新对局。
- **AI 难度分级**：支持“入门（轻快）”、“进阶（均衡）”、“大师（深思）”三档难度。
- **悔棋（Undo）**：支持随时悔棋撤回上一回合，并支持键盘快捷键 `Z`。
- **音效系统**：基于原生 Web Audio API 合成真实清脆的木盘落子声与提子轻响，支持顶栏静音开关。
- **显示落子手数**：顶栏一键切换盘面手数显示（1, 2, 3...），最后一手高亮焦点光环。
- 玩家可选择执黑先行，或执白后行（AI 执黑时会自动开局）。
- 点击交叉点落子，支持悬停预览、落子弹性动画、最后一手标记与键盘光标落子。
- 停一手、认输、终局数子与结果面板。
- 提子、禁自杀、简单劫规则。
- 中国规则数子，白棋贴 3.5 子；双方连续停一手后终局。
- **复盘与分析**：
  - 逐手胜率走势折线图与各选点胜率前三。
  - **着法评级**：根据前后胜率自动打标“妙手”、“好手”、“缓手”、“恶手”。
  - **步进控制**：支持 `⏮ 首手`、`◀ 上一手`、`下一手 ▶`、`末手 ⏭` 按钮及键盘 `←` / `→` / `Home` / `End` 快捷翻盘。
  - **SGF 棋谱导出**：终局或复盘时一键导出标准 `.sgf` 文件并自动复制到剪贴板，兼容主流围棋软件。
- 最近 8 局会自动保留在本次会话中，可从复盘面板或“复盘历史对局”按钮切换查看。
- AI 会把“停一手”作为候选着法参与搜索，在终局或形势领先时主动停一手。
- 响应式布局，针对手机端竖屏排版深度优化。

## 复盘

一局结束后点击结果面板中的“复盘本局”，或使用侧栏的“复盘历史对局”按钮：

- 每个局面都会用与实战一致的 PUCT + RAVE MCTS 评估所有非自填真眼的合法点（包括停一手），默认对每个局面运行 `REVIEW_ITERATIONS = 2400` 次迭代推演，并按棋盘 D4 对称性归约等效选点、对低访问实战着法单独补充校验。
- 表格列出每一手的实战胜率（行棋方视角）、该手之前的推荐前三（含胜率占优的停一手）、以及实战着法在全部候选中的排名。
- 折线图展示每手之后的黑棋实时胜率；点击折线节点或表格行，可在左上角的小棋盘上查看当时的局面、推荐点（编号 1 / 2 / 3）与实战落点（红色虚线圈）。
- 复盘分析通过多线程 Web Worker 池（最多 4 线程并行）执行，不会阻塞当前对局；分析进度会实时显示。
- 迭代次数可在 `app.js` 顶部的 `REVIEW_ITERATIONS` 调整，数值越大结果越稳定、耗时越长。

## AI 设计

AI 位于 `ai.js`，使用基于增量链气棋盘（FastBoard）的 PUCT + First-Play RAVE 蒙特卡洛树搜索：

- 基于预计算的 MoGo 3×3 局部棋型表、吃子/救打吃/连接/断/做眼先验与 D4 对称归约引导树搜索，使关键局部变化在有限时间内可深入至十余层。
- 推演采用零分配 FastBoard 引擎与局部打吃救子、3×3 棋型、无偏空点采样策略，单次推演持续落子至双停或至少 **18 手**（`MIN_LOOKAHEAD_PLIES = 18`），并使用胜负为主、目数差（`tanh`）引导的复合效用避免大优缓手与垃圾送吃。
- 默认每步思考约 2.1 秒；HTTP 模式下运行于 `ai-worker.js`，不阻塞界面。直接打开本地文件时自动降级为主线程计算。
- 所有树节点均从当前行棋方视角最大化效用并结合下置信界（LCB）选点，避免对手“配合”AI 走棋。
- 停一手始终是一个候选着法：对手刚停一手且当前数子领先时直接终局；其余情况由目数引导搜索自然判断是否已无可争之目。
- 终局使用中国规则数子，比较黑白双方盘面加贴子后的胜负。

搜索时间、贴子、复盘推演次数等参数可在 `app.js` 与 `ai.js` 顶部的常量中调整。

## 关于 GPU 加速

结论：**当前规模下不建议使用 GPU，暂未接入 WebGPU/WebGL 计算。**

原因：

1. 棋盘只有 5 × 5 或 6 × 6，单次推演的计算量很小；MCTS 是高度分支化、逐手依赖的控制流，GPU 擅长的宽向量并行在这里收益有限。
2. 每次扩展/模拟都需要读写棋盘、提子与气，规则判断包含大量分支；在着色器中实现完整围棋规则（提子、劫、眼、数子）复杂且容易出错，CPU 上几行代码的逻辑在 GPU 上会变成大段分支代码。
3. WebGPU 的调度、数据上传/回读开销通常大于一个小棋盘单次推演本身；把每个节点都提交一次 GPU dispatch 反而更慢。
4. 当前 CPU 单线程大约每秒可完成数千次推演；复盘一局通常只需数秒，而且已经放在独立 Worker 中执行。

更划算的加速方向是：增加 Web Worker 数量并行分析多个局面、使用 WebAssembly 优化热点，或在棋盘扩大（如 19 路）或引入神经网络策略/价值网络后再考虑 GPU 批量推理。若未来确实需要 GPU，优先考虑“批量并行推演”而不是逐节点 MCTS。


## 文件结构

```text
weiqi/
├── index.html      页面结构
├── styles.css      视觉样式与响应式布局
├── engine.js       围棋规则、提子、劫、数子
├── ai.js           MCTS 搜索、停一手与复盘逐点分析
├── ai-worker.js    AI / 复盘 Web Worker 入口
├── app.js          界面交互、棋盘绘制、对局流程与复盘面板
└── README.md
```

## 说明

- 双方连续停一手后按中国规则数子终局，`engine.js` 会以双活安全（seki-safe）的死子清理规则自动移除被健康敌棋围死且无法做两眼的棋块，不包含手动点目标记死子的流程。
- 若想更深入调整 AI 强度，可增大 `app.js` 中的 `LEVEL_CONFIG` 搜索时间，或调整 `ai.js` 中的 `MIN_LOOKAHEAD_PLIES` 与 PUCT/RAVE 参数。
