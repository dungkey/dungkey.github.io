# 2026-11-05

## 修复 3D 书架开书/合书动画（封皮丢失、瞬移、触发诡异）

根因（用无头 Chrome + CDP 逐帧驱动 `v.update(dt)` 复现并验证）：

- **起点尺寸/中心错位**：`openBook` 直接把 `runtime.group.scale`（=1）当作特写书本缩放，但特写闭合外形是 1.19×1.67、实体书只有 0.84×1.12；且 root 原点在书脊、闭合书视觉中心在 +closedCenterX。结果点击瞬间书放大 1.4 倍并向右平移半本，看起来「瞬移到中间」。
- **飞行缓动**：旧的 `1-(1-p)^3.2` 第一帧就走完约 1/4 路程，加剧瞬移感。
- **闭合中心偏移未乘缩放**：`halfW/2` 是本地单位，特写缩放 0.785 时闭合书偏左，展开阶段再横滑一大截。
- **封面**：阅读器一律重画深绿烫金牌，导入 EPUB 的 `coverDataUrl` 封面图在动画里丢失；经典书也没把 `THEMES[theme]` 布面色传进来。
- **暗场遮挡 + 光照突变**：背景幕布固定在相机前 2.5，飞书前半程书在幕布之后被压暗，越过幕布时封面突然变亮；阅读灯挂在 root 下但 target 留在世界原点，光向随书移动剧烈变化，且 root 隐藏时整组灯瞬间熄灭。
- **关闭**：`closeBook` 改用 `body.position/quaternion` 且缩放当 1，落点与开书起点不一致。
- **触发延迟**：`openBookById` 先 `await` IndexedDB 读正文才启动动画。

改动（`src/bookViewer3D.js` + `src/scene.js`）：

- 新增 `captureShelfTransform`（按实体书 W/H 换算 `shelfScale`≈0.671）、`applyClosedOffset`（书脊原点 = 视觉中心 − closedCenterX×scale）、`refreshCloseUpTransform`、`positionBackdrop`（幕布跟着书退到其后 0.18）、`setReadingLights`（灯组移到 scene、target 一并挂入、强度渐入渐出）。
- `flyIn/flyOut` 合并为同一套「视觉中心插值 + 当前姿态/缩放偏移」，EaseInOutCubic；`unfold/fold` 合并为互逆的 closed 系数插值，四段首尾姿态连续。
- 新增 `setCoverPlate`/`applyCoverTexture`/`disposeCoverPlate`：优先复用书架已解码的封面图（独立 `CanvasTexture`，不共享 source，避免 dispose 连累书架），无图时按 `palette.cloth` 生成同色烫金牌；封面图按 cover-fit 居中裁切。`scene.js` 的 `createBookVisual` 返回可变 `coverArt.texture` 引用，`addBookRuntime` 带 `bookW/bookH`。
- `scene.js` 补齐经典书有效 palette，`openBookById` 不再 await 数据库，`chaptersPromise` 传给 `prepareBookContent` 在分页前等待。
- 开书时清掉上一本书页面贴图、重置 flip 叶片状态；`onResize` 同步刷新 closeUp 姿态。

验证：`node --check` 通过；逐帧截图量得开书首帧封面 bbox (529,262)-(660,443) 与书架原书 (522,261)-(662,445) 基本重合；合书结束画面与初始书架**逐像素完全一致**（平均差 0.0）；封面亮度沿飞书平滑 98→127、合书 127→100 无跳变；EPUB 封面图与共享贴图两条路径、真实点击开书→Esc 合书全链路无控制台错误。

## 修复开合时「书变扁」（厚度不匹配）

- 根因：`build3DViewer` 把特写书的**厚度写死**（闭合 0.126，约书宽 0.10），而书架实体书厚度由页数决定（`computeBookThickness` 0.09~0.45，约书宽 0.11~0.54）。实测《宿命之环》（t≈0.42）点击瞬间厚度从 0.418 掉到 0.101（约 1/5），合上飞回书架又弹回 0.42 —— 即「点开变扁、退出后又变厚」。
- 改法：新增 `BookViewer3D.setBindingDepth(闭合书厚)`，按 D 重算封板厚度与位置、纸堆切面、曲面页弧度、书脊、堵头布，并在 `openBook` 里按 `runtime.thickness / runtime.bookW` 换算后重建（`createPageTrimGeometry`、`createCurvedPageGeometry` 增加厚度参数）。开合全程与实体书同比例。
- 三个连带细节：①书脊「后凸量」固定 0.03（若随厚度放大，厚书轮廓会比实体书胖一圈）；②脊弧在 X 做压缩 `spineScaleX`，避免厚书把闭合宽度撑大；③`applyClosedOffset` 增加厚度方向 `depthCenterZ` 偏移（闭合书视觉中心不在书脊轴线上）。
- 验证（无头 Chrome + CDP，导入 6.3MB 真实 EPUB）：首帧 厚 0.4202/宽 0.8464/高 1.12 对书架 0.4161/0.8518/1.1066，三维都在 1% 内；飞书→展开→翻页→合书无控制台报错，合书后书架厚度回到 0.4212。
- 测试提示：headless 下 rAF 会被节流，动画需靠 `Page.captureScreenshot` 或手动 `v.update(dt)` 步进（脚本 /tmp/shelf-thick.mjs、/tmp/shelf-visual.mjs、/tmp/shelf-regress.mjs）。

## 修复点击后「书脊直接缺失」（左视角最明显）

- 复现：无头 Chrome + CDP，导入 `/Users/dungkey/飞牛同步/网文/宿命之环.epub`，把相机移到书的 -X（书脊）一侧；点击第一帧书脊那面变成一大片白色内页文字，书架上的《宿命之环》印刷书脊整块消失。
- 根因：`BookViewer3D` 只有 `spineMesh`（展开态中缝用的半圆柱，位于 z 负侧的薄薄一片），**闭合态外书脊没有几何面**；`createPageTrimGeometry` 也只做书口/天头/地脚，不做书脊侧封口。厚书 D≈0.595 时 spineR 被 clamp 到 0.17，只覆盖约 1/3 书厚，剩余部分直接看穿到 `leftPageMesh`。之前厚度修复放大了 D，这个洞随之变明显。
- 改法（`src/bookViewer3D.js` + `src/scene.js`）：
  - 新增 `closedSpineMesh`：半圆柱 `CylinderGeometry(D/2+0.0015, …, thetaStart=π, thetaLength=π)`，theta π→2π 正好是朝 -X 外凸、z 覆盖整段书厚的弧面；再按 `spineBulgeX=clamp(D*0.058,0.006,0.04)` 压扁 X，形状对齐书架的 `spineArtMesh`。
  - `scene.js` 的 `createBookVisual` 把 `spineCanvas` 通过 `spineArt` 交给 runtime；`setSpineArt()` 用独立 `CanvasTexture`（不共享 source，避免 dispose 连累书架）复用书架上印好书名的画布。经典书无印刷书脊时用 `createClassicSpineCanvas()` 近似画布面/烫金竹节/纸题签。
  - `applySpineMorph(closed)`：外书脊与内书脊互斥过渡（外书脊 X/Z 随 closed 收缩进中缝，内书脊反向长出），并让堵头布只在摊开后可见（闭合时会从书脊上下角露出两个暗红小点）。在 flyIn/flyOut 恒定 1、unfold/fold 用 `closed` 插值、展开完成 0、合拢完成 1。
  - `depthCenterZ` 改为 0（外书脊前后对称）、`closedCenterX` 改用 `spineBulgeX`。
- 验证：左视角点击首帧书脊书名/烫金带/菱形/作者与书架原书连续，文字不镜像不倒置；经典书与 6.6MB EPUB 两条路径均可开书→翻页→合书，无控制台错误；合书后左视角书架与点击前 **PSNR=inf（逐像素一致）**，书架 `spineTex` 贴图完好（422×1024）。
- 测试脚本：`/tmp/shelf-spine.mjs`（左视角复现）、`/tmp/shelf-spine-regress.mjs`（双书型全链路）、`/tmp/shelf-spine-cycle.mjs`（EPUB 开合循环 + 贴图存活）、`/tmp/shelf-spine-classic.mjs`（经典书回退贴图）。本轮 headless Chrome 启动参数需 `--no-sandbox --disable-gpu-sandbox --no-proxy-server --enable-unsafe-webgpu --use-angle=swiftshader --use-webgpu-adapter=swiftshader`，且本地 `python3 -m http.server 8765` 与 Chrome 都必须用后台任务方式常驻。

## 修复「开合位置不一致」与残留阴影（真实时间线复现）

之前逐帧手动步进的测试把 `v.update` 换成空、`controls.update` 换成 noop，等于冻结了相机和物理，掩盖了真实运行时的漂移。这次改用 CDP 按真实时间推进 + 每帧 trace（`/tmp/shelf-pos-diag.mjs`、`/tmp/shelf-pos-scenarios.mjs`、`/tmp/shelf-final-check.mjs`），定位到：

- **相机阻尼是主因**：`controls.enabled=false` 不阻止 `controls.update()` 应用惯性；`animate()` 每帧仍调用。拖完视角立刻点书，相机在飞书+展开的 1.2s 内又移动 1.3 单位，而 `closeUpPos` 是开书瞬间算的固定世界坐标 → 展开书投影 NDC `[-1.00, 0.59]`（飞出屏幕），合书后视角也停在别处。
- **resize 不同步**：`onResize()` 遇 `isAnimating` 直接 return；动画中 resize 触发 `fitCamera()` 把相机从 z=9.54 推到 11.45，`closeUpPos/closeUpScale` 仍旧值 → 展开书缩到约半屏。
- **实体书没被冻结**：`updateBooks` 每帧仍同步 group 并调用 `updateBookVisualDetails`，把 `openBook` 刚关掉的阴影重新点亮（实测开书期间 49 帧全为 true）；hover 抬升、入场缩放、物理微动也让 `closeBook` 重捕获的落点偏离起飞点。
- **阴影残留**：书飞走后书架上留一块孤立影子。

改动（`src/bookViewer3D.js` + `src/scene.js`）：
- 开书时清 `_sphericalDelta` + `_scale`、`enableDamping=false` 后 `controls.update()` 一次并 `camera.updateMatrixWorld(true)`，彻底定格；`animate()` 在 `isOpen` 时跳过 `controls.update()`；flyOut 结束恢复 damping。
- `update()` 每帧 `refreshCloseUpTransform()`（动画里直接引用 `closeUpPos/Quat` 对象，copy 更新即生效）；`onResize()` 动画中只刷参数、静止时摆 root；新增 `shiftShelfAnchor(dx)` 供 resize 重映射书架时修正落点。
- `closeBook()` 不再 `captureShelfTransform`，落点严格沿用起飞点。
- `scene.js` 新增 `readingFreeze`：开书时记录 book 的 `pos/angle/pitch/yaw` 与视觉 `visualPos/visualQuat`（保留 hover 抬升，只把入场 scale 归 1）；`updateBooks` 对冻结书逐帧钉住物理与视觉姿态、跳过 `updateBookVisualDetails`、保持 `shadow.visible=false`，合书动画结束自动解冻；`handleResize` 同步修正 `shelfPos.x`。

验证：静止开合 group 位置/四元数前后差 <3e-4、相机差 0、阴影全程 false；拖视角后开书相机 0 位移、NDC (0,0)；动画中 resize 后 root 贴合 closeUpPos 且缩放自适应 0.785→0.766；展开态 resize、翻页、二次开合、6.2MB EPUB 厚书开合循环与书脊贴图（422×1024）均正常，无控制台错误。注：合书后 z 的 0.015 变化来自鼠标移开时 hover 抬升平滑回落，属正常交互。
