## 大书（5MB EPUB）打开等待约 10s 的性能修复

- 根因：`PageLayoutEngine.paginateBook` 对整本书逐字符 `measureText`（5MB 书约百万次 canvas 调用、自定义字体下极慢）；35MB 字体在 CSS 里声明 3 个 @font-face 别名、JS 又 new 两个 FontFace 重复加载解析；`openBook` 把字体等待 + 全量分页串在飞书动画之前，用户看到的是静止书架。
- 排版：新增 `breakParagraph`——单字符宽度缓存 + Float64 前缀和二分断行 + 每行 1 次精确 `measureText`（kerning 时局部回退/补齐），断行与旧算法 100% 一致；`invalidateWidthCache()` 在字体就绪/字号变化时重置度量；分页结果按「书籍 id + fontScale」缓存在 `BookViewer3D.paginationCache`（最多 3 本）。
- 字体：`styles/main.css` 只留 1 个 @font-face；`ensureCustomFontLoaded()` 改为一次 `document.fonts.load` 并导出 `isCustomFontReady()`；`scene.js` 在 `init()` 首行预热。
- 打开流程：`openBook` 同步启动 flyIn 动画，`prepareBookContent()` 后台等字体 + 两帧后分页（rAF + 120ms 定时器兜底、`contentToken` 防竞态）；`scene.js` 空闲时最多预取 3 本书正文（IndexedDB → 内存）。
- 导入：`epub.js` 的 `extractText` 加解压缓存，章节 HTML 批量并行解压（8/批），块级节点 `children.length` 快路径，每 16 章让出主线程。
- 验证：无头 Chrome + CDP（临时 `_perf-test.html` / `_open-test.html` / 6.5MB 测试 EPUB 均已清理）。1.2M 字符：旧断行 1.2~1.4s → 新完整分页约 0.2s，55461 行断行零差异；6.5MB / 400 万字符 / 250 章：导入 0.77s、点击到动画 2ms、分页 0.1s 内、缓存命中 0ms、10750 页无错误；真实页面（SwiftShader）字体 face 数 1、字体可用、导入链路正常。README 增补「大书打开性能」小节。
